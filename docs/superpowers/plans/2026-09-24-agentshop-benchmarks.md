# AgentShop showcase and benchmarks: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A realistic example app in this repository, **AgentShop**, whose ~90 scenarios run unchanged in three
modes: **headless** (`agentshopctl test`), **simulator through the bridge** (`agentshopctl app run`) and
**XCUITest**. A benchmark script times every scenario in every mode and writes a report, and a video script
records the simulator runs side by side with the headless run.

**Architecture:** Port the AgentShop PoC (`~/Developer/Projects/bartosz/agent-first-ios-poc`) into
`Examples/AgentShop` as **one** SwiftPM package that depends on this repository by path. Extend it with an
Onboarding flow and a Shop flow (feed → product → cart → checkout → confirmation). The scenario files (`.appctl`)
are the single source of truth. The XCUITests are **generated** from them: the generator runs each scenario
headlessly to learn which screen every command is sent on, then emits taps and typing against accessibility
identifiers that follow one fixed convention. The benchmark and video scripts only orchestrate existing CLIs:
`agentshopctl`, `xcodebuild`, `simctl` and a Swift/AVFoundation composer.

**Tech stack:** Swift 6.1+, TCA 1.26, SwiftUI (iOS 18), XCTest/XCUITest, Python 3 (stdlib only) for the generator
and the benchmark, and Swift + AVFoundation for the video composer. `ffmpeg` here has no `drawtext`, so it is not
used.

**Spec:** this document. It came out of the conversation of 2026-09-24. Decisions taken there:
- "The shop is fine, just add more functionality": port AgentShop, don't grow TinyApp. TinyApp stays the
  package's small test fixture.
- Three groups: **authentication**, **onboarding**, **shop** (the "feed"), with **20–40 scenarios per group**.
- No change to the library (`Sources/`) unless it is unavoidable. Focus on benchmarks and demos.
- A simulator video that shows the difference visually.

## Global constraints

- No edits under `Sources/` or `Tests/` of the root package. If one turns out to be unavoidable, stop and say so.
- `Examples/AgentShop/Package.swift` depends on `.package(path: "../..")`. Its identity is the repository
  directory's name, so product references say `package: "agentctl-ios"`. The README must note that the
  checkout directory has to be named `agentctl-ios`, which is the `git clone` default.
- iOS deployment target 18.0; `swift-tools-version: 6.1`; strict concurrency complete (as in the PoC).
- The CLI root is `Examples/AgentShop`: `target: .project("App/AgentShop.xcodeproj", scheme: "AgentShop")`, so the
  root marker is the project. `packages: ["."]`, `scenariosPath: "scenarios"`, `docsPath: "agent-commands.md"`,
  and `invocation: "./appctl"` (the wrapper in `Examples/AgentShop`).
- Scenario file names are `<group>-<name>.appctl` with group ∈ {`auth`, `onboarding`, `shop`}, flat in
  `scenarios/`, because `ScenarioRunner` does not recurse.
- A scenario is **comparable** (runs in all three modes) iff it uses none of `advance`, `login-as` or `reset`.
  Only comparable scenarios go into the cross-mode numbers. At least 90% of each group must be comparable.
- Both simulator modes run with `-mock-latency 0` and `-clear-session`, so the benchmark measures the harness
  and not the fake backend.
- Generated files carry a `// GENERATED by bench/gen_uitests.py — do not edit` header and are committed.
  `--check` fails CI when they are stale.
- Benchmark output: the report goes to `docs/benchmarks/<YYYY-MM-DD>-agentshop.md` (committed). Raw JSON and
  videos go to `Examples/AgentShop/.bench/` (gitignored). Videos are not committed: the report links a path
  and the user uploads the video to the README.

## Review focus

1. **A UI identifier missing from a view**: the generated test must fail with the identifier and the scenario
   line in its message, not with a bare timeout.
2. **Keyboard covering a button** after typing: `tap` scrolls or dismisses the keyboard before tapping.
   Pinned by `auth-register-happy-path`, which has a long form.
3. **A `mock` line whose call index a real UI run reaches differently**, for example when the view fires
   `onAppear` twice. The generator derives the index from the headless calls, and a UI test that sees an
   unexpected state fails with a message that names the scheduled fault.
4. **Stale generated tests after a scenario edit**: `gen_uitests.py --check` in CI.
5. **The bridge port already taken** by a previous run: the benchmark terminates the app before each launch
   (`app launch` already does `simctl terminate`), and the UI tests use `-agent-port 0`.

## Conventions

### Accessibility identifiers (the contract between views and generated UI tests)

`<Screen>` is the Swift type name of the `AgentScreen`, the name `screens` prints in brackets (`Login`,
`ProductDetail`).

| What | Identifier | Notes |
|---|---|---|
| Screen marker | `screen:<concrete path>` | e.g. `screen:home/shop/101`. Put `.accessibilityElement(children: .contain).accessibilityIdentifier(...)` on the screen's root container (`FormScreen` gets a `screenID:` parameter). |
| Command without an argument | `<Screen>.<command>` | `Login.submit`, `Cart.checkout` |
| Command with a free-text argument (`<text>`, `<digits>`, `<number>`) | `<Screen>.<command>` | a text field; typing replaces its contents |
| Command with `<on\|off>` | `<Screen>.<command>` | a switch or checkbox with `.accessibilityValue(isOn ? "on" : "off")` |
| Command with a choice argument (anything else) | `<Screen>.<command>.<argument>` | `HomeTabs.tab.cart`, `ShopFeed.open.101`, `Interests.toggle.shoes` |
| Container `back` | `nav.back` | the design system's `BackButton` default; a screen that shadows `back` uses `<Screen>.back` |
| Summary value shown on screen | `<Screen>.<key>` | `.accessibilityValue(<the exact summary string>)` on the element that shows it; for a text field that is the command's own field |
| Error | `error:<code>` | on the error message view, whatever screen shows it |

The generator treats the element for a command source that is a container (`HomeTabs`, `AuthFlow`) with the
container's name as `<Screen>`.

### Summary keys that UI tests do not check

`loading`, `revealed`, `pending`, `call=` and `calls=` are not visible, or are timing-dependent. The generator
skips them and counts each skip, and the report prints "N assertions checked headlessly only". Keys named `can*`
map to `isEnabled` of the command whose gate hint is `<key>=false`, taken from the `screens` output.

### Scheduled faults (how a UI test forces a backend error)

A UI test cannot type `mock orders.fetchOrders network`, so it passes launch arguments instead:
`-mock-fault orders.fetchOrders#2=network` means "the 2nd call to `orders.fetchOrders` fails with `network`".
Every client in AgentShop goes through `shopCall`, not `mockCall` directly:

```swift
// Sources/Models/ShopCall.swift (Models is imported by every client)
import AgentCtlCore
import Dependencies
import Foundation
import Synchronization

/// Faults scheduled at launch for UI tests, which cannot send `mock`: `-mock-fault <method>#<n>=<code>` makes the
/// n-th call to `<method>` fail with `<code>`. Headless runs and the bridge use `mock` instead and leave this empty.
public final class ScheduledFaults: Sendable {
  private let state: Mutex<(plan: [String: [Int: String]], counts: [String: Int])>

  public init(arguments: [String] = []) {
    var plan: [String: [Int: String]] = [:]
    var iterator = arguments.makeIterator()
    while let argument = iterator.next() {
      guard argument == "-mock-fault", let spec = iterator.next() else { continue }
      // orders.fetchOrders#2=network
      let parts = spec.split(separator: "=", maxSplits: 1)
      let target = parts.first?.split(separator: "#") ?? []
      guard parts.count == 2, target.count == 2, let index = Int(target[1]) else { continue }
      plan[String(target[0]), default: [:]][index] = String(parts[1])
    }
    state = Mutex((plan, [:]))
  }

  /// Counts a call to `method`, and returns the code scheduled for this call, if any.
  public func next(_ method: String) -> String? {
    state.withLock { state in
      let count = state.counts[method, default: 0] + 1
      state.counts[method] = count
      return state.plan[method]?[count]
    }
  }
}

extension ScheduledFaults: DependencyKey {
  public static let liveValue = ScheduledFaults()
  public static var testValue: ScheduledFaults { ScheduledFaults() }
}

extension DependencyValues {
  public var scheduledFaults: ScheduledFaults {
    get { self[ScheduledFaults.self] }
    set { self[ScheduledFaults.self] = newValue }
  }
}

/// Every AgentShop client method goes through here: it arms a scheduled fault for this call, then `mockCall`.
public func shopCall<T: Sendable>(
  _ name: String,
  error makeError: @Sendable (String) -> any Error,
  _ body: @Sendable () async throws -> T
) async throws -> T {
  @Dependency(\.scheduledFaults) var scheduled
  @Dependency(\.mockFaults) var faults
  if let code = scheduled.next(name) {
    faults.set(name, code: code)
  }
  return try await mockCall(name, error: makeError, body)
}
```

`AgentShopConfig.live` sets `deps.scheduledFaults = ScheduledFaults(arguments: ProcessInfo.processInfo.arguments)`.
Headless leaves the empty default.

`ShopUITestCase` API (the generator emits only these calls):

```swift
class ShopUITestCase: XCTestCase {
  var app: XCUIApplication!
  func launch(faults: [String] = [])        // -clear-session -mock-latency 0 -agent-port 0 + "-mock-fault", f…
  func tap(_ id: String, line: String)       // wait ≤10 s, scroll until hittable (≤6 swipes), tap
  func type(_ id: String, _ text: String, line: String)  // tap, clear, typeText
  func setSwitch(_ id: String, _ on: Bool, line: String) // tap only if value differs
  func back(line: String)                    // tap "nav.back"
  func expectScreen(_ path: String, line: String)        // "screen:<path>" exists within 10 s
  func expectValue(_ id: String, _ value: String, line: String) // label or value == value within 5 s
  func expectEnabled(_ id: String, _ enabled: Bool, line: String)
  func expectError(_ code: String, line: String)         // "error:<code>" exists within 5 s
  func expectNoError(line: String)           // no element whose identifier BEGINSWITH "error:"
}
```

Every failure message includes `line` (`auth-login-happy-path.appctl:7 submit`).

`gen_uitests.py`:
1. `agentshopctl screens` → per path pattern: the screen name, and its commands (name, argument placeholder,
   source, gate hint).
2. Per scenario: skip it if it isn't comparable. Run `agentshopctl run --json "<file contents>"`. For step *i*,
   the screen the command is sent on is step *i-1*'s `screen`, matched against the patterns.
3. Emit calls per the convention. For `mock M C`: the index = 1 + the number of `M` calls in all earlier steps'
   `calls`, emitted as a launch fault. A `mock` that follows a non-`mock` command is still a launch argument,
   because the call index is what makes it fire at the right moment.
4. Write one file per group, with `test_<scenario_with_underscores>` methods in order. `--check` regenerates
   into memory and diffs.

### Task 6: `bench/bench.py` (the three-mode benchmark and its report)

```
python3 Examples/AgentShop/bench/bench.py [--runs 3] [--groups auth,onboarding,shop] [--modes headless,bridge,uitest]
                                          [--sim "iPhone 17 Pro"] [--scenarios <glob>] [--quick]
```

Phases, each printed as it goes:
1. **Setup:** resolve the simulator (same rule as the CLI: booted, then released, then newest), boot it, and wait
   for `bootstatus -b`. Build `agentshopctl` (timed), then `xcodebuild build-for-testing` (timed, `-derivedDataPath
   .bench/DerivedData`, `-skipMacroValidation`) and install the app.
2. **Headless:** for each comparable scenario, time `agentshopctl test <file>` (the binary, `APPCTL_ROOT` set) over
   `--runs` runs and take the median; also parse the in-process `(N steps, X ms)`. Also time one
   `agentshopctl test` over each whole group, and over the headless-only scenarios.
3. **Bridge:** per comparable scenario, `agentshopctl app launch --no-build --clear-session --latency 0 --sim <udid>`
   (timed: launch), then `agentshopctl app run "<file>"` (timed: run), and record PASS/FAIL. One run each.
4. **UI tests:** per group, `xcodebuild test-without-building -xctestrun <file> -destination id=<udid>
   -only-testing:AgentShopUITests/<Group>UITests -parallel-testing-enabled NO` (timed wall clock). Parse
   `Test Case '-[AgentShopUITests.<Class> <test>]' passed (N seconds)` into per-scenario times.
5. **Report:** `docs/benchmarks/<date>-agentshop.md`, containing:
   - the machine, the tools and the simulator;
   - a per-group summary table: scenarios, steps, headless total, bridge total (launch + run), UI tests (sum of
     tests and the xcodebuild wall time), and speed-ups;
   - the one-off costs (CLI build, build-for-testing);
   - per-scenario tables in `<details>`;
   - the headless-only scenarios, with the real time they would need to wait (the sum of their `advance`s);
   - checked vs headless-only assertions;
   - caveats.
   Raw JSON goes to `.bench/<timestamp>.json`.
